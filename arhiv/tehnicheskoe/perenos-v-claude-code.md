# Перенос проекта Виолы в Claude Code. Промпты по шагам

Выполнять по порядку, каждый промпт отдельной задачей. Между шагами проверять результат.

---

## Шаг 0. Руками, до запуска Claude Code

1. Создать папку проекта, например `~/violamaro`.
2. Скачать из чата пять файлов базы и положить в папку: `kanon-viny.md`, `golos-viola.md`, `tehniki-viola.md`, `printsipy-viola.md`, `reestr-istochnikov.md`.
3. Положить туда же два транскрипта: запись лид-магнита и ответы Виолы голосом. Назвать `01-lidmagnit.txt` и `02-otvety.txt`.
4. Открыть терминал в этой папке, запустить `claude`.

## Шаг 1. Структура

```
Разложи файлы в этой папке по структуре и создай недостающие директории.

В пустые директории положи README.md на две-три строки с описанием, что туда класть.

Ничего не переписывай внутри файлов, только перемещай.
```

```
Прочитай все файлы в baza/ полностью, затем создай CLAUDE.md в корне.

Контекст проекта, который нужно туда занести:

Проект: запуск линейки онлайн-продуктов психотерапевта Виолы Маро. Виола эксперт и методолог, живёт в Италии, 25 лет практики. Я продюсер, отвечаю за маркетинг, продажи, тексты. В команде также Артём (контент, трафик) и Аня (документы, продажи).

Запуск: август-октябрь 2026. Лид-магнит про чувство вины, событие 1990 руб в сентябре, флагманский курс осенью. Воронка: короткие видео и YouTube, дальше Telegram-канал violamaro1, дальше анкета предзаписи, дальше продажи.

Что должно быть в CLAUDE.md:

1. Описание проекта и участников, коротко.
2. Карта файлов: что где лежит, какой файл является источником правды по какому вопросу.
3. Обязательное правило: перед написанием любого текста от лица Виолы прочитать baza/golos-viola.md целиком и нужный тематический файл. Не писать по памяти.
4. Правило про метки: в базе [Д] это её дословные слова, [П] пересказ, [В] невподтверждённый вывод. В тексты можно ставить [Д] как есть, [В] нельзя использовать вообще.
5. Красные линии, перенеси их из baza/printsipy-viola.md: без обещаний результата, без упоминания стажа и регалий, без заочных диагнозов, обезличивание клиентских случаев, двойная гендерная разметка ролей, термин только после бытового объяснения.
6. Правило про конструкцию «не X, а Y»: запрещена в продающих текстах, разрешена в экспертном контенте от лица Виолы, потому что это её собственный способ мышления.
7. Как отвечать мне: короткие структурированные блоки с заголовками, без лишних пояснений и без похвалы. Давить критикой, а не соглашаться. Не менять позицию без новых данных. Считать проверяемое скриптом, а не на глаз.
8. Правило «В базу?»: если в ходе работы появляется материал, который стоит добавить в базу, спрашивать меня об этом отдельным блоком в конце ответа.
9. Технические лимиты: подпись к видео в Telegram 1024 знака, обычный пост 4096.

Пиши плотно, без воды. CLAUDE.md читается в каждой сессии, каждая лишняя строка стоит контекста.
```

## Шаг 3. Скрипт проверки текста

```
Создай skripty/proverka.py.

Назначение: проверить готовый текст, написанный от лица Виолы, перед отправкой ей.

На вход путь к текстовому файлу. На выход отчёт в консоль.

Что считать:
1. Количество знаков, слов, предложений. Средняя длина предложения. Её норма 11-12 слов, предупреждать если меньше 7 или больше 14.
2. Доля предложений до 5 слов. Норма 20-30%, предупреждать если меньше 15%.
3. Количество предложений длиннее 30 слов. Норма ноль, любое такое предложение выводить целиком.
4. Частота слова «вот» на 1000 слов. Её норма около 20, предупреждать если меньше 8.
5. Наличие запрещённых слов, она их вычищает сама при записи: допустим, кстати, значит, прям, слушайте, смотрите, послушайте, короче. Выводить каждое найденное с контекстом.
6. Частота «очень» на 1000 слов, норма до 4, предупреждать при превышении.
7. Конструкции «не ..., а ...», выводить все найденные с пометкой, что в продающем тексте они запрещены.
8. Проверка длины под лимиты Telegram: 1024 и 4096.

Отдельная функция: сверка с корпусом. Разбить текст на предложения, для каждого проверить, встречается ли оно дословно в файлах korpus/. Вывести таблицу: фрагмент, найден в корпусе или нет. Нормализовать перед сравнением: нижний регистр, ё в е, схлопывание пробелов.

Запуск: python3 skripty/proverka.py путь/к/тексту.txt

Код простой, только стандартная библиотека, без внешних зависимостей.
```

## Шаг 4. Скрипт разбора транскрипта

```
Создай skripty/razbor.py.

Назначение: обработать новый транскрипт Виолы и показать, что в нём есть нового относительно уже собранной базы.

На вход путь к новому транскрипту. На выход отчёт.

Что делать:
1. Метрики регистра: слов, предложений, средняя длина, доля коротких фраз, частота маркеров «вот», «и вот», «очень», «то есть», «именно», «допустим», «кстати», «значит». Вывести рядом со средними по существующему корпусу, чтобы было видно, это сырая речь или отредактированная запись.
2. Список тем, которых нет в baza/kanon-viny.md. Проверять по ключевым словам, список слов задать в начале скрипта переменной, чтобы я мог его править.
3. Найти в транскрипте предложения, которые выглядят как определения или формулировки техник: содержат «это всегда», «это когда», «нужно», «я говорю», «называется», «техника». Вывести их списком как кандидатов на добавление в базу.
4. Найти образы и метафоры: сверить с уже известным списком из baza/golos-viola.md раздел 6, вывести отдельно те, которых там нет.

Запуск: python3 skripty/razbor.py korpus/новый.txt

Только стандартная библиотека.
```

## Шаг 5. Команды

```
Создай директорию .claude/commands/ и в ней четыре файла с командами.

proverka.md — прогнать указанный текст через skripty/proverka.py, показать отчёт и дать вывод, что править. Обязательно сначала прочитать baza/golos-viola.md.

post.md — написать пост для Telegram-канала Виолы. Перед написанием прочитать baza/golos-viola.md и baza/kanon-viny.md. После написания прогнать через skripty/proverka.py и показать метрики вместе с текстом. Строить текст на её дословных формулировках с меткой [Д] из базы, свои связки помечать отдельно в разборе после текста.

transkript.md — обработать новый транскрипт: положить в korpus/, прогнать skripty/razbor.py, показать что нового, предложить конкретные добавления в файлы базы с указанием раздела. Ничего не записывать в базу без моего подтверждения.

dyrki.md — собрать из всех файлов baza/ разделы с открытыми вопросами к Виоле и вывести единым списком с указанием, из какого файла каждый вопрос.
```

## Шаг 6. Git и облако

Сначала руками: зайти на github.com, создать **приватный** репозиторий `violamaro`, без README и без .gitignore, пустой.

Приватность обязательна. В репозитории окажутся клиентские случаи с подробностями, условия договора и финансовые цифры.

```
Инициализируй git в этой папке.

Создай .gitignore: исключи системный мусор (.DS_Store, Thumbs.db), временные файлы, окружения Python, кэш.

Сделай первый коммит со всей текущей базой, корпусом и скриптами.

Добавь remote и запушь в ветку main:
https://github.com/andzenho/violamaro

Дальше допиши в CLAUDE.md раздел про работу с git:

1. Проект синхронизируется между несколькими машинами через репозиторий https://github.com/andzenho/violamaro
2. В начале каждой сессии первым делом делать git pull и сообщать мне, если пришли изменения.
3. После каждого обновления любого файла в baza/ делать отдельный коммит. В описании коммита указывать, что изменилось и на основании какого источника.
4. В конце сессии напоминать мне про git push, если есть незапушенные коммиты.
5. Если при pull возникает конфликт, не разрешать его самостоятельно, показать мне обе версии и спросить.
```

### На второй и последующих машинах

Один раз в терминале, в той папке, где хотите держать проект:

```
git clone https://github.com/andzenho/violamaro
cd violamaro
claude
```

Дальше всё как обычно. CLAUDE.md, база и скрипты приедут вместе с репозиторием.

### Правило работы, чтобы не ловить конфликты

Начали работу — `git pull`. Закончили — `git push`. Claude Code сделает это сам, если попросить, а с правилами из CLAUDE.md будет напоминать.

Главный риск: поработать на второй машине, не сделав pull. Тогда две версии базы разойдутся, и придётся сводить руками. Привычка делать pull первым действием снимает проблему полностью.

## Шаг 7. Проверка, что всё работает

```
Прочитай baza/golos-viola.md и baza/kanon-viny.md.

Напиши пост для Telegram-канала Виолы на тему различия вины и стыда. Длина до 1500 знаков. Строй на её дословных формулировках из базы.

После текста прогони его через skripty/proverka.py и покажи отчёт. Отдельно перечисли, какие фрагменты взяты из корпуса дословно, а какие написаны нами.
```

Если седьмой шаг отработал целиком и метрики сошлись, перенос закончен.
