# skripty/

Служебные скрипты. По умолчанию — только стандартная библиотека Python 3.

- `proverka.py` — проверка готового текста от лица Виолы перед отправкой.
  `python3 skripty/proverka.py путь/к/тексту.txt`
- `razbor.py` — разбор нового транскрипта: что нового относительно базы.
  `python3 skripty/razbor.py korpus/новый.txt`
- `yt_comments.py` — выгрузка комментариев из-под видео/Shorts через YouTube Data
  API v3 (работает из облака, не скрейпинг). Только stdlib; нужен ключ
  `YOUTUBE_API_KEY`. Сырьё кладётся в `analitika/kommentarii/`.
  `python3 skripty/yt_comments.py <ссылка> | --channel <канал>`
- `razbor_kommentov.py` — разбор собранных комментариев для анализа ЦА: топ по
  лайкам, фигуры вины, ярлыки, сигнал по углам С1–С5, боли, биграммы. Только stdlib.
  `python3 skripty/razbor_kommentov.py analitika/kommentarii/<...>/*.jsonl`
- `sheets_sync.py` — синхронизация контент-плана из `kontent/kp/` в Google-таблицу
  «Рабочее пространство» (репозиторий → таблица, только колонки «Тема / идея» и
  «Текст поста»). Установка и настройка — `kontent/kp/README.md`.
  `python3 skripty/sheets_sync.py --list-tabs | (без флага) | --apply`
- `ca_sync.py` — синхронизация анализа ЦА из `analitika/ca-data.json` в Google-таблицу
  «ЦА и продукты» (репозиторий → таблица, лист = вкладка; форматирование и твои
  доп-колонки не трогает). Настройка — `analitika/README.md`.
  `python3 skripty/ca_sync.py --list-tabs | (без флага) | --apply`

- `bot_probe.py` — кому бот может написать первым: прогоняет список Telegram ID
  через Bot API (`sendChatAction`, без видимых сообщений) и по каждому даёт
  вердикт — reachable / no_access (нет разрешения писать) / blocked. Нужен для
  аудита людей из мини-аппа, которые в чат бота не писали. Только stdlib; токен —
  `TG_BOT_TOKEN`. Вход — файл с ID по строке или CSV с колонкой `userId`.
  `TG_BOT_TOKEN=... python3 skripty/bot_probe.py ids.txt [--out otchet.csv]`

- `sait.js` — открыть сайт настоящим Chromium и снять сырьё: текст в порядке
  чтения, структуру (заголовки, CTA, формы, цены), ссылки, скриншот. Нужен там,
  где `WebFetch` бесполезен: Tilda, Taplink, любой SPA. Node, не Python; разовая
  настройка — `sh skripty/sait_setup.sh`. Вызывается и командой `/sait`.
  `node skripty/sait.js <адрес>`

- `graf.sh` — граф знаний по репозиторию (graphify): собрать, спросить, найти
  связь между двумя понятиями, показать самые связанные узлы. Что индексируется —
  `.graphifyignore` (`arhiv/`, `skripty/`, `docs/` выключены). Выход —
  `graphify-out/`, в git не коммитится. Ставится `pip install graphifyy`.
  Границы применения — ниже, читать до первого запуска.
  `sh skripty/graf.sh sborka | obnovit | vopros "…" | svyaz "A" "B" | uzel "X" | uzly | otchet | status`

`sheets_sync.py`, `ca_sync.py` и `graf.sh` — **скрипты с внешними зависимостями**.
Первые два (Google Sheets API нельзя вызвать без библиотеки) ставятся из
`skripty/requirements-sheets.txt` и используют один ключ сервис-аккаунта.
`graf.sh` требует `graphifyy` (`pip install graphifyy`); отдельный API-ключ не
нужен — извлечение идёт через локальный `claude` по подписке, а если задан
`GEMINI_API_KEY`, то через Gemini (дешевле и быстрее на объёме `korpus/`).

## Граф знаний: что он делает и чего не делает

**Делает.** Отвечает на вопросы вида «где во всём репозитории всплывает Х» и
«как связаны А и Б» одним запросом вместо обхода 130 файлов. Сильные места на
нашем материале:
- `korpus/` — 92 тыс. слов сырой речи в 13 транскриптах, самый неиндексированный
  кусок. Граф отвечает, в каком транскрипте и рядом с чем Виола говорила про Х.
- сквозная проверка после разворотов 11.08 и 19.08: где в `produkt/` и
  `kontent/` ещё живут снятые цена, название и рамка.
- `analitika/` — какая боль из ЦА в каких файлах повторяется и чем подтверждена.

**Не делает.** Граф — навигация и аудит, **не источник правды**:
1. Он **не отменяет правило воронки текста**. Перед текстом от лица Виолы
   `baza/golos-viola.md` читается целиком, из файла, а не пересказом из графа.
   Голос — это ритм и лексика, они не переживают сжатие в узлы и рёбра.
2. Он **не переносит метки** `[Д]/[П]/[В]`. У graphify своя разметка
   достоверности (EXTRACTED / INFERRED / AMBIGUOUS), и она про другое: INFERRED —
   это связь, которую модель достроила сама, то есть ровно наш `[В]`. Ни одна
   фраза не идёт в текст «потому что так в графе»: сначала открываем файл-источник
   и смотрим метку там.
3. Он **не знает про архив**. `arhiv/` выключен намеренно (`.graphifyignore`):
   пущенный в граф, старый флагман всплывал бы в ответах наравне с текущим курсом.
   Значит, на вопросы про историю проекта граф отвечать не должен — там читаем
   `arhiv/README.md` руками.

**Порядок внедрения.** Сначала пилот на одной папке — `graphify extract korpus
--backend claude-cli --out /tmp/pilot` — и глазами проверить, что узлы по-русски
осмысленные, а не транслитерированная каша. Русский на этом материале никем не
проверялся. Каша — граф не наш инструмент, дальше не идём. Осмысленно —
`sh skripty/graf.sh sborka` на весь репозиторий.
