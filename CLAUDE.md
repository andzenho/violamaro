# Проект «Виола Маро»

## О проекте
Запуск линейки онлайн-продуктов психотерапевта Виолы Маро. Виола — эксперт и методолог, живёт в Италии. По образованию психолог, психотерапевт (её формулировка 12.08; «эмпатолог» — слово аудитории, в наши тексты не идёт). Продюсер (я) — маркетинг, продажи, тексты. Команда: Артём — контент и трафик, Аня — документы и продажи.

Запуск: август–октябрь 2026. Воронка: короткие видео и YouTube → Telegram-канал `violamaro1` → продукт-вход → флагман.

**Курс после разворота 11.08 (созвон с Виолой):** ушли от вина/токсик-аудитории — она бедная (макс 50–60 € по её оценке). Флагман — **«Любовь и деньги»** для платёжеспособного эмпата: «эмпатия-суперсила → отношения и деньги», сборка её курсов «Эмпатия» + «Ключи», облегчённая. Тарифы **19 900 / 29 900 / 39 900 ₽**. Вина/жертва остаётся механизмом внутри и темой дешёвого входа. Разбор созвона — `produkt/sozvon-viola-11.08-itogi.md`, действующая стратегия — `produkt/strategiya.md`.

**⚠️ Открыто:** продукт-вход не решён — событие 1990 ₽ (собиралось под старую ЦА) против дешёвого входа 60–70 € (её логика объёма). Пока не выбрано, прогрев писать не из чего.

  - `kanon-lyubov-i-dengi.md` — канон по теме «любовь и деньги». Смысловое ядро флагмана.
  - `kanon-viny.md` — канон по теме вины. Механизм внутри и тема лид-магнита, не витрина.
  - `tehniki-viola.md` — техники и упражнения.
  - `printsipy-viola.md` — принципы и красные линии.

## Правило воронки текста (обязательно)
Перед написанием любого текста от лица Виолы — прочитать `baza/golos-viola.md` **целиком** и нужный тематический файл базы. **Не писать по памяти.**

## Парадигма продуктов (обязательно)
Все продукты и тексты строим как **трансформацию состояния человека** — его энергии, тела, позиции, голоса — её образами (плита → свет). Не «тема/работа с виной», а метаморфоза «из А в Б». Канон и сетка трансформаций — `produkt/transformatsii.md`. Заголовок/оффер = обещание сдвига состояния; превращение внутреннее (не «обстоятельства/он изменятся»). Какую метаморфозу продавать (по карте внимания канала) — `produkt/transformatsiya-za-dengi.md`: `эмпат-жертва → исцелившийся эмпат`, линза «сила и её адресат». Враг-витрина токсик/манипулятор — только для трафика: в продукте его почти нет, люди приходят разбираться с собой. **Ведущий фрейм:** эмпатия — суперсила, заблокированная виной; задача продукта — разблокировать и направить на себя (дар остаётся, меняется адресат). «Суперспособность/суперсила» — язык витрины, в прямую речь Виолы без её визирования не ставим. Слово «эмпат» разрешено и в теле текста: оно вошло в её голос («дорогие мои эмпаты»).

## Метки в базе
- `[Д]` — дословные слова Виолы. В тексты можно ставить как есть.
- `[П]` — пересказ.
- `[В]` — невподтверждённый вывод. **В тексты не использовать вообще.**
- Источники (в базе рядом с метками): `[ЗАП]` запись лид-магнита (её редактура под камеру), `[ОТВ]` ответы голосом (сырая речь), `[СЦ]` наш забракованный сценарий — только для контраста. Ни метки, ни источники в опубликованный текст не переносить.

## Google-таблица (контент-план)
- Таблица «Виола // Рабочее пространство» — витрина для слежения за контентом. Источник правды всё равно репозиторий (`kontent/kp/`).
- Синхронизация односторонняя: **репозиторий → таблица**. В таблице руками правим что угодно, кроме колонок «Тема / идея» и «Текст поста» (`Суть`) — их перезаписывает `sheets_sync.py`.
- Скрипт пишет только в эти две колонки и только в существующие строки (по дате). Строки, разметку, формулы и объединения не трогает — дизайн таблицы не ломается.
- Перед записью — всегда сухой прогон (`python3 skripty/sheets_sync.py`), потом `--apply`.
- Как запустить синхронизацию (для ассистента в любой сессии):
  1. Ключ сервис-аккаунта: переменная окружения `VIOLA_SHEETS_CREDS_B64` (JSON в base64 — рекомендуется, надёжно проходит через `.env`), либо `VIOLA_SHEETS_CREDS_JSON` (сам JSON), либо файл `skripty/.google-creds.json`. Нет ключа — попросить продюсера прикрепить его.
  2. Зависимости: `python3 -m pip install -r skripty/requirements-sheets.txt` (в новом окружении может понадобиться `pip install cffi`).
  3. `python3 skripty/sheets_sync.py` (сухой прогон) → показать продюсеру → `--apply`.
- Настройка доступа и формат постов — `kontent/kp/README.md`.

## Git и синхронизация
1. Источник правды — ветка `main` репозитория https://github.com/andzenho/violamaro. Все машины клонируют и работают с `main`.
2. `git pull` в начале сессии — автоматически, через SessionStart-хук (`.claude/settings.json`). Просить продюсера не нужно. Если пришли изменения — коротко сообщить.
3. После каждого обновления любого файла в `baza/` — отдельный коммит. В описании указывать, что изменилось и на основании какого источника.
4. `git push` — делать самому в конце работы, без напоминаний и без вопросов. Не оставлять незапушенных коммитов.
5. При конфликте (хук с `--ff-only` при расхождении просто откажется тянуть) — не разрешать самостоятельно. Показать обе версии и спросить.
