# Проект «Виола Маро»

## О проекте
Запуск линейки онлайн-продуктов психотерапевта Виолы Маро. Виола — эксперт и методолог, живёт в Италии, 25 лет практики. Продюсер (я) — маркетинг, продажи, тексты. Команда: Артём — контент и трафик, Аня — документы и продажи.

Запуск: август–октябрь 2026. Лид-магнит про чувство вины → событие 1990 руб в сентябре → флагманский курс осенью. Воронка: короткие видео и YouTube → Telegram-канал `violamaro1` → анкета предзаписи → продажи.

**⚠️ Разворот 11.08 (созвон с Виолой):** уходим от вина/токсик-аудитории — она бедная (макс 50–60 €). Флагман пересобираем под **платёжеспособного эмпата**: «эмпатия-суперсила → отношения и деньги» (сборка её курсов «Эмпатия» + «Ключи», облегчённая). Вина/жертва — только дешёвый вход. Цена флагмана вниз (~30 000 ₽). Полный разбор — `produkt/sozvon-viola-11.08-itogi.md`; статус связанных файлов (`strategiya.md`, `transformatsiya-za-dengi.md`, тарифы) — переписывается.

## Карта файлов (где источник правды)
- `baza/` — база знаний, **источник правды**. Только проверенные материалы с меткой источника.
  - `golos-viola.md` — голос Виолы: лексика, ритм, образы, запреты. Правда по стилю.
  - `kanon-viny.md` — канон по теме вины. Правда по содержанию темы.
  - `tehniki-viola.md` — техники и упражнения.
  - `printsipy-viola.md` — принципы и красные линии.
  - `reestr-istochnikov.md` — реестр источников.
- `korpus/` — сырьё: неотредактированные транскрипты. Только исходники, ничего больше. Переработка идёт `korpus → baza`, никогда наоборот. Транскрипты можно снимать плагином `/watch` (видео/YouTube → транскрипт с таймкодами, Whisper/субтитры) — вывод кладём в `korpus/` как есть.
- `produkt/` — программы, цены, условия продуктов. `strategiya.md` — стратегия запуска (верхний уровень), `voronka.md` — канон воронки (тема → вход/глубина, витрина vs двигатель), `transformatsii.md` — канон трансформаций (продукты/тексты как смена состояния), `transformatsiya-za-dengi.md` — какую метаморфозу продавать ради максимальной выручки (карта внимания канала), `ofer-ya-vybirayu-sebya.md` — скелет оффера флагмана (два слоя языка, метаморфоза, первый экран), `produkty-viola-staryye.md` — разбор её старых лендингов (Лабиринт, Ключи): цены, образы, тарифы, откуда имена «Неудобная»/«Лабиринт», `fakty-viola.md` — факты и решения от Виолы.
- `kontent/` — посты, сценарии видео.
- `analitika/` — цифры, отчёты, гипотезы. **ЦА — два направления (разворот 11.08):** платящая (эмпат/деньги, под флагман) — `ca-master.md` (сводка) + `ca-empatia.md` + `ca-klyuchi.md`; старая (вина/токсик, бедная, под лид-магнит/дешёвый вход) — `ca-framework.md`, `ca-analiz-v1.1.md`, `ca-lidmagnit.md`, `ca-ya-vybirayu-sebya.md`, `anketa-pervye-dannye.md`, `vozrazheniya-i-prodazhi.md`. Сквозное — `ca-voc.md` (язык), `ca-data.json`. Карта — `analitika/README.md`.
- `skripty/` — стандартная библиотека, кроме google-синхронизаций. `proverka.py`/`razbor.py` (текст/транскрипт), `yt_comments.py`+`razbor_kommentov.py` (комментарии YouTube → разбор ЦА), `sheets_sync.py` (контент-план → таблица) и `ca_sync.py` (ЦА → таблица) — требуют google-библиотек.
- `kontent/kp/` — источник правды по контент-плану, синхронизируется в Google-таблицу. Одна папка на вкладку КП, `_tab.txt` = имя вкладки, файлы постов по датам. Формат и настройка — `kontent/kp/README.md`.

## Правило воронки текста (обязательно)
Перед написанием любого текста от лица Виолы — прочитать `baza/golos-viola.md` **целиком** и нужный тематический файл базы. **Не писать по памяти.**

## Парадигма продуктов (обязательно)
Все продукты и тексты строим как **трансформацию состояния человека** — его энергии, тела, позиции, голоса — её образами (плита → свет). Не «тема/работа с виной», а метаморфоза «из А в Б». Канон и сетка трансформаций — `produkt/transformatsii.md`. Заголовок/оффер = обещание сдвига состояния; превращение внутреннее (не «обстоятельства/он изменятся»). Какую метаморфозу продавать ради максимальной выручки (по карте внимания канала) — `produkt/transformatsiya-za-dengi.md`: `эмпат-жертва → исцелившийся эмпат`, линза «энергия/сила», враг-витрина — токсик/манипулятор. **Ведущий фрейм:** эмпатия — суперсила, заблокированная виной; задача продукта — разблокировать и направить на себя (дар остаётся, меняется адресат). Слова «эмпат/суперспособность» — язык витрины, не голос Виолы.

## Метки в базе
- `[Д]` — дословные слова Виолы. В тексты можно ставить как есть.
- `[П]` — пересказ.
- `[В]` — невподтверждённый вывод. **В тексты не использовать вообще.**
- Источники (в базе рядом с метками): `[ЗАП]` запись лид-магнита (её редактура под камеру), `[ОТВ]` ответы голосом (сырая речь), `[СЦ]` наш забракованный сценарий — только для контраста. Ни метки, ни источники в опубликованный текст не переносить.

- Короткие структурированные блоки с заголовками. Без лишних пояснений и без похвалы.
- Давить критикой, а не соглашаться.
- Не менять позицию без новых данных.
- Проверяемое — считать скриптом, а не на глаз.

## Технические лимиты
- Подпись к видео в Telegram — 1024 знака.
- Обычный пост — 4096 знаков.

## Google-таблица (контент-план)
- Таблица «Виола // Рабочее пространство» — витрина для слежения за контентом. Источник правды всё равно репозиторий (`kontent/kp/`).
- Синхронизация односторонняя: **репозиторий → таблица**. В таблице руками правим что угодно, кроме колонок «Тема / идея» и «Текст поста» (`Суть`) — их перезаписывает `sheets_sync.py`.
- Скрипт пишет только в эти две колонки и только в существующие строки (по дате). Строки, разметку, формулы и объединения не трогает — дизайн таблицы не ломается.
- Перед записью — всегда сухой прогон (`python3 skripty/sheets_sync.py`), потом `--apply`.
- Как запустить синхронизацию (для ассистента в любой сессии):
  1. Ключ сервис-аккаунта: переменная окружения `VIOLA_SHEETS_CREDS_B64` (JSON в base64 — рекомендуется, надёжно проходит через `.env`), либо `VIOLA_SHEETS_CREDS_JSON` (сам JSON), либо файл `skripty/.google-creds.json`. Нет ключа — попросить продюсера прикрепить его.
  2. Зависимости: `python3 -m pip install -r skripty/requirements-sheets.txt` (в новом окружении может понадобиться `pip install cffi`).
  3. `python3 skripty/sheets_sync.py` (сухой прогон) → показать продюсеру → `--apply`.
- Настройка доступа и формат постов — `kontent/kp/README.md`.

## Git и синхронизация
1. Источник правды — ветка `main` репозитория https://github.com/andzenho/violamaro. Все машины клонируют и работают с `main`.
2. `git pull` в начале сессии — автоматически, через SessionStart-хук (`.claude/settings.json`). Просить продюсера не нужно. Если пришли изменения — коротко сообщить.
3. После каждого обновления любого файла в `baza/` — отдельный коммит. В описании указывать, что изменилось и на основании какого источника.
4. `git push` — делать самому в конце работы, без напоминаний и без вопросов. Не оставлять незапушенных коммитов.
5. При конфликте (хук с `--ff-only` при расхождении просто откажется тянуть) — не разрешать самостоятельно. Показать обе версии и спросить.
